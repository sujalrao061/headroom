# Fast publication path

The public website can run in **recorded-evidence mode** on Vercel. It reads the checked-in GPU reports, shows their capture time, and disables fresh GPU runs when the Python runner is offline. Judges can ask Nemotron to make a **new runtime choice about the recorded measurements** after the server-side Nebius key is configured. The GPU measurement and model response are labeled separately. This does not provide a fresh public GPU benchmark.

1. Publish this folder as a public GitHub repository named `headroom` under the project owner's account. Keep `.env` files, `.torch-deps`, `node_modules`, and `reports` out of the repository; `.gitignore` already excludes them.
2. Import that repository as a Next.js project in Vercel. Use the repository root, `pnpm install`, and `pnpm build`. The recorded site works without environment variables, but “Ask Nemotron now” will report that it is not configured.
3. In the Vercel project's server-side environment variables, set `NEBIUS_API_KEY` to a private, active Nebius Token Factory key. Set a low account spending limit before enabling public calls. Never use a `NEXT_PUBLIC_` prefix or put the key in the repository. Redeploy so the server route receives the variable. The route sends only fixed saved evidence, caps model output, and has a best-effort in-memory cooldown; it does **not** have durable abuse protection for broad public traffic.
4. Open the deployed URL in a private browser window. Verify all three saved point-cloud cases, the recorded attention comparison, and the evidence labels. Check that “Live GPU runner offline” is disabled and “Ask Nemotron now” returns an explicitly live response. Inspect browser source/network responses to confirm the key is absent.
5. For a fresh **GPU-backed** public run, host the bounded Python runner separately on suitable GPU compute, configure network/auth protections, and point `HEADROOM_RUNNER_URL` on Vercel to that service. Keep the key out of the frontend and repository. The current runner binds to loopback intentionally and is not ready to expose directly to the Internet.
6. Record the app making a live Nemotron decision about the saved GPU evidence, and include the local GPU runner measurement footage if possible. Upload a video shorter than three minutes publicly to YouTube. Add the demo, repository, and video URLs to `SUBMISSION.md` and the Devpost entry.

The [official rules](https://nebiusglobalaihackathon.devpost.com/rules) require a working demo URL, public open-source repository with setup instructions, public YouTube video, project description, and feedback on the Nebius/NVIDIA tools used. The listed deadline is October 30, 2026 at 10:00 a.m. Pacific time. Verify the submission form before final entry.
